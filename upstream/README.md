# Выбор API для переноса

`ignore.json` — редактируемый список отложенного публичного API и единственный
механизм выбора API на всех этапах разработки. Всё, что не исключено, участвует
в переносе и проверке совместимости.

Список инициализирован из публичных TypeScript-объявлений Puppeteer 24.36.1.

Секции:

- `classes`: целиком исключённые публичные классы. Удаление имени включает класс
  со всеми его публичными членами. Чтобы включить только часть, одновременно добавьте
  остальные члены в `members`.
- `members`: исключённые члены активных классов, включая методы, свойства и явно
  объявленные публичные конструкторы. Удаление `Page.title` включает только этот член.
  `Class.member` — instance API, `Class::member` — static API.
- `exports`: исключённые самостоятельные runtime-экспорты пакета, например `launch`
  и `default`. Type-only объявления разрешаются при анализе сигнатур отдельно.

Наследуемые члены учитываются под именем класса, через который они доступны.
Например, исключение EventEmitter не исключает Browser.on: для него нужна отдельная
запись. Перегрузки одного метода имеют один ID и включаются вместе.

Все имена точные, без шаблонов. Новый класс или член активного класса не добавляется
в ignore автоматически. Исключение класса распространяется также на его новые
члены. Устаревшая запись (удаление/переименование upstream API) выдаёт диагностику.

При расширении переноса разработчик или агент удаляет записи из ignore, запускает
синхронизацию и проверки, затем реализует методы и тесты. Повторной генерации ignore
в обычном updater нет. `initializedFrom` — версия первоначального заполнения, а не
ограничение на проверку следующих версий пакета.

## Доступно сейчас

```sh
composer upstream-report
composer test-tooling
```

Первая команда только читает публичные объявления установленного Puppeteer и
ignore, выводит активные классы/члены/экспорты и устаревшие записи. Версии установленного
puppeteer и puppeteer-core должны совпадать с package.json. Вторая проверяет
инвентаризацию и правила исключений. Для инструментов требуется Node.js 18+ и
установленные npm-зависимости проекта.

Однократная инициализация была выполнена командой:

```sh
node tools/upstream/ignore.cjs init --keep=Puppeteer.connect,Browser.createBrowserContext,BrowserContext.newPage,Page.goto,Page.evaluate,BrowserContext.close,Browser.disconnect
```

`init` отказывается перезаписывать существующий файл. `report` его не изменяет.

## Предусмотрено для следующих инструментов

Генератор PHP-заготовок и поиск тестов будут использовать общий `selectApi()`.
Они пока не реализованы. Методы, классы и их тесты из ignore не создаются автоматически.
Ignore не удаляет уже написанные файлы и не разрешает скрывать ошибки их PHP-кода.

Связанные типы потребуется разрешать для понимания активных сигнатур; текущий
экстрактор пока выдаёт только имена и виды членов. Например, Page.goto возвращает
HTTPResponse|null. Генератор должен показать необходимый тип, а разработчик/агент
может написать его PHP-представление как часть реализации Page.goto, не меняя ignore
и не перенося автоматически все методы HTTPResponse. Ignore ограничивает генерацию
и обязательный API, а не устройство ручной реализации.

Для тестов учитываются только сценарии активного API. Общие fixtures/hooks такого
сценария входят в его сопровождение. Если сценарий использует исключённый метод
как вспомогательный шаг, это показывается в отчёте; ignore сам не изменяется.
При переносе теста подготовку можно выразить через fixture или активный API,
сохранив проверяемое поведение. Пилот должен проходить с текущим ignore проекта.
