# Фреймворк сопровождения нативного Puppeteer PHP

Статус в `v3`: пункт 1 выполнен для текущих ignore-файлов; PHP-клиент и его тесты
содержат заглушки.

Порядок команд и восстановление после сбоя — в [README](../README.md#development-workflow).
Практические настройки и коды завершения — в [README](../README.md#configuration),
форматы данных — в [upstream/schemas](../upstream/schemas).

## Цель и ответственность

Перенести публичный API и наблюдаемое поведение Puppeteer на PHP, затем сопровождать
обновления тем же фреймворком. Runtime клиента — PHP, Amp v3/Fibers, WebSocket и
необходимые браузерные протоколы, начиная с CDP. Код для страницы остаётся JavaScript.
Node.js используется инструментами разработки.

| Уровень | Ответственность |
| --- | --- |
| `update-php` | Получить upstream, извлечь API и типы, обновить PHP-объявления, каталог тестов и PHPUnit-заготовки |
| Psalm и PHPUnit | Независимо проверить PHP-типы и поведение; запускаться напрямую через PHP |
| Разработчик или агент | Разобрать изменения, задать необходимые mappings, реализовать методы и перенести assertions |

Перенос охватывает публичные контракты и поведение; внутреннюю архитектуру PHP-клиента
выбирает разработчик. Объявления из внутренних файлов учитываются, если они входят
в публичные типы.

Инструменты запускаются локально и независимо в порядке, указанном в README.

## Входы, данные и охват

Версия Puppeteer в `package.json` точная; `package-lock.json` коммитится.
SourceResolver проверяет npm-зависимости и при необходимости выполняет
`npm ci --ignore-scripts`. Upstream-тесты берутся из Git на неизменной ревизии,
соответствие которой версии пакета проверено.
`--offline` требует установленного пакета и готового кеша.

`composer.json` задаёт диапазоны PHP-зависимостей библиотеки и хранится в Git.
`composer.lock` остаётся локальным. Установка библиотеки потребителем не должна
запускать npm или требовать Node.

| Путь | Назначение |
| --- | --- |
| `upstream/config.json` | Ручные соответствия классов, членов, типов и тестов |
| `upstream/ignore.json` | Исключения API: точные имена в `classes`, `members`, `exports` |
| `upstream/test-ignore.json` | Исключения тестов: точные ID с причинами |
| `upstream/lock.json` | Версии источников/инструментов и ревизия upstream-тестов |
| `upstream/api.json`, `upstream/tests.json` | Генерируемые каталоги для ревью изменений |
| `upstream/schemas/` | Версионируемые описания JSON-форматов |
| `tools/upstream/`, `tools/php/` | Анализ TypeScript, преобразование типов и PHP AST-синхронизация |
| `src/`, `tests/Parity/`, `tests/Unit/` | PHP-клиент, PHPUnit-тесты публичного поведения, тесты PHP-компонентов |
| `.build/upstream/` | Локальный кеш исходников |

Конфигурация и каталоги коммитятся; кеш остаётся локальным.

Ignore-файлы определяют охват. Общий `selectApi()` применяется при генерации
объявлений и отборе тестов. Удаление исключения включает API. Новый член активного класса по умолчанию
активен, включая вновь обнаруженный публичный конструктор; исключённый класс
остаётся исключённым целиком. Наследуемые члены учитываются под именем принимающего класса.

Генератор не меняет ignore. `initializedFrom` и `init --keep` относятся только к
первоначальному заполнению. Устаревшие исключения диагностируются. Обычно ignore
сокращается; ранее созданные исключённые тесты удаляются вручную. PHPUnit продолжает
запускать существующие тесты, а Psalm — проверять существующий PHP-код.

Необходимые типы активных сигнатур получают supporting-заготовки независимо от
API-ignore. Например, `HTTPResponse` нужен для `Page.goto`, но это не включает
все методы `HTTPResponse`. Интерфейсы с методами получают supporting-контракт;
данные без методов обычно представляются array shapes. Внутренние PHP-помощники
могут не иметь upstream-аналога.

## Генерация типов и PHP

TypeScript Program/TypeChecker разрешает публичные экспорты, наследование, aliases,
классы, интерфейсы, enums, события, конструкторы, свойства/accessors и overloads.
Каталог сохраняет связанные типы параметров и результатов, qualified names и
исходные позиции. Пути и строки помогают навигации, но не определяют семантический diff API.

Mapper сохраняет вложенные shapes, литералы, коллекции, tuples, index/mapped types,
union/intersection, callbacks и generics в Psalm. Нативные объявления совместимы с
PHP 8.1 и могут быть шире аннотаций. `number` соответствует `int|float`,
`Promise<T>` — `Amp\Future<T>`, `Promise<void>` — `Amp\Future<null>`.

Optional, nullable и `undefined` различаются: необязательный ключ shape можно
опустить, явный `null` сохраняется. Defaults и неоднозначные overloads задаются явно.
`any`/`unknown` и статически неизвестный результат JS-строки допускают `mixed`;
потерянная структура типа всегда диагностируется. Рекурсивные shapes, зависимые
utility-типы без эквивалента Psalm и variadic tuples требуют явного mapping.
В текущем охвате нерешённых типов нет; расширение API может потребовать новых правил.

Принятые различия PHP/JS: `evaluate` принимает JS-строку и возвращает `Future<mixed>`;
callbacks на стороне PHP остаются типизированными `callable`; `AbortSignal`
соответствует `Amp\Cancellation`. Точные правила и defaults находятся в конфигурации.

PHP AST-синхронизатор изменяет объявления и выделенные генерируемые PHPDoc-блоки.
Тела, assertions, ручные комментарии, атрибуты, initializers и внутренние методы
сохраняются.

| Изменение | Действие генератора |
| --- | --- |
| Новый класс/член | Создать объявление; тело метода выбрасывает `LogicException` с `NotImplemented` |
| Изменённая сигнатура | Обновить объявление и аннотации, сохранить тело |
| Удалённый член | Сохранить PHP-код и сообщить `obsolete`; удаление вручную |
| Переименование | Считать добавлением/удалением до явного сопоставления |
| Конфликт ручного объявления | Сохранить конфликтующую часть и сообщить о конфликте |
| Изменение только приватной реализации JS | Не менять PHP структурно; при обновлении повторить проверки поведения |

PHPDoc содержит `@see` на исходный тест или объявление в GitHub с точным коммитом и
строкой. Генератор обновляет ссылки, проверяет синтаксис и записывает файлы напрямую.
Повторный запуск с теми же входами ничего не меняет. Перед генерацией работа коммитится;
после сбоя файлы восстанавливаются из Git.

CLI показывает progress bar в терминале, версию/ревизию, изменённые файлы и компактную
диагностику. Статистика разделяет активный API, supporting-типы, синхронизированные
объявления и API с сопоставленными upstream-тестами. Проценты имеют явные знаменатели
и не означают готовность реализации. `--json` содержит полные данные без оформления.

## Сопровождение тестов

Синхронизация каталога и запуск PHPUnit независимы. TestTracker сопоставляет
проверяемый публичный API с `PHPUnit class::method`. ID сценария состоит из пути,
иерархии `describe`/`it` и варианта параметризации. Имена PHP-тестов берутся из upstream;
хеш нужен только при коллизии. Выданные имена и явные mappings сохраняются.

Связь подтверждается subject теста и типами receiver либо ручным mapping.
Вспомогательный вызов `goto`/`evaluate` не делает метод предметом проверки.
Неоднозначные, динамические и повторяющиеся случаи остаются видимыми кандидатами
для ручной классификации. Переименование теста — добавление/удаление до сопоставления.

| Статус | Значение |
| --- | --- |
| `required` | Проверяет активное API; при отсутствии создаётся `markTestIncomplete()` |
| `excluded-api` | Всё проверяемое API исключено |
| `excluded-test` | Сценарий явно исключён с причиной |
| `unresolved` | Требуется уточнить связь; это кандидат, а не обязательный тест |

Смешанный сценарий сохраняет проверку активного поведения. Отсутствие required-теста
у активного API показывается как пробел сопоставления, даже если все тесты исключены.
Тестовые hooks/helpers/fixtures отслеживаются по файлам, чтобы замечать изменения
сценариев публичного поведения.

Разработчик переносит setup, действия и assertions в PHP. Изменённые upstream-тесты
дают диагностику; PHP-тела не перезаписываются. Если подходящего upstream-теста нет,
добавляется собственный PHPUnit-тест с привязкой к API. HTML и данные можно разделять;
вспомогательные вызовы исключённого API заменять без изменения проверяемого поведения.

Каталог коммитится вместе с проверенными PHP-тестами. Эквивалентность assertions
проверяется при ревью. PHPUnit запускает PHP-тесты напрямую; исходные JS-тесты при
необходимости запускаются отдельно штатным upstream-исполнителем. При изменении общего транспорта
выполняется весь текущий PHPUnit-набор. Incomplete/skip не подтверждают совместимость.

## План выполнения

«Выполнить пункт N» означает выполнить его целиком, проверить критерии и представить
результат; следующий пункт автоматически не начинается. Все пункты следуют правилам
выше. Недостатки генератора исправляются в том пункте, где обнаружены.

### Пункт 1. Реализовать инструменты фреймворка

**Выполнен для текущего охвата.** Получение upstream, извлечение API/типов,
PHP AST-синхронизация, supporting-заготовки, каталог тестов, PHPDoc-ссылки, CLI,
конфигурация Psalm и PHPUnit реализованы.

Критерии: все необходимые типы текущих сигнатур представлены корректно; генерация
не имеет конфликтов, сохраняет ручной код и повторяется без изменений; Psalm проходит;
PHP-тесты инструментов проходят. Клиентские заглушки и incomplete-тесты допустимы.

### Пункт 2. Реализовать классы и тесты по текущим ignore-файлам

Сгенерировать объявления и реализовать активный API, транспорт WebSocket/CDP,
Amp/Fibers, отмену, ошибки и освобождение ресурсов. Перенести обязательные тесты,
разобрать относящиеся к охвату неоднозначные mappings.

Критерии: охват зафиксирован на начало пункта и не сокращён ради прохождения;
нет активных заглушек, нерешённых типов и незавершённых обязательных тестов;
Psalm и PHPUnit проходят, включая конкурентность, ошибки и закрытие ресурсов;
повторная генерация ничего не меняет.

### Пункт 3. Перенести остальной публичный API

Удалять исключения группами, генерировать, реализовывать и проверять новые классы
и тесты тем же фреймворком. Включить запуск браузера и протоколы целевой версии.
Независимые группы можно поручать субагентам: один владелец на файл, общие инструменты
и транспорт координируются отдельно.

Критерии: API-ignore пуст для целевой версии; test-ignore содержит только обоснованные
ограничения среды, а не неперенесённые возможности; нет заглушек и необъяснённых
расхождений; полный PHPUnit-набор и Psalm проходят, включая ранее перенесённый API.

### Пункт 4. Проверить обновление версии и подготовить выпуск

В изолированной копии проверить переход с ближайшей подходящей предыдущей
опубликованной версии Puppeteer на текущую целевую. Зафиксировать версии и результаты,
проверить diff API/тестов, сохранение тел, необходимые ручные правки и повторную генерацию.
Основную целевую версию проекта эксперимент не меняет.

Критерии: обновление воспроизводимо; после адаптации проходят Psalm и PHPUnit полного
API; чистая установка и работа PHP-библиотеки обходятся без Node/npm в runtime;
JS-инструменты устанавливаются по npm lock, PHP-зависимости — по composer.json;
проверены локальные команды, обновлены документация и описание выпуска.

### Пункт 5. Реализовать нативные версии популярных плагинов Puppeteer

Зафиксировать список и версии плагинов, начиная с `puppeteer-extra-plugin-stealth`.
Каждый порт размещается в `plugins/<name>/` с тестами, документацией и браузерным JS.
Управляющая логика работает на PHP через клиент; плагины подключаются явно.
Клиент работает и без плагинов.
Добавляются только нужные hooks запуска/подключения, новых страниц и закрытия ресурсов
с сохранением Amp/Fibers и порядка обработчиков.

Критерии: реализован согласованный список; указаны исходный пакет, версия/ревизия,
лицензия, настройки и отличия; PHPDoc содержит закреплённые ссылки; Psalm и PHPUnit
клиента/плагинов проходят, включая инициализацию, ошибки, новые страницы и совместную
работу. Все методы реализованы, управляющий код выполняется на PHP. Описаны подключение,
настройка и обновление портов; assertions перенесены вручную, тестовые данные локальны.
